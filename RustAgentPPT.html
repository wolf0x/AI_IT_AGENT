01 背景：为什么需要端侧 IR Agent

应急响应（Incident Response）是高度时间敏感的场景。当 Windows 主机可能被入侵时，需要在最短时间内完成：

  • 采集：进程、服务、网络连接、持久化项、事件日志、驱动……
  • 分析：YARA 扫描、进程行为评分、持久化枚举、时间线重建
  • 报告：生成结构化报告，包含 IOC 和 MITRE ATT&CK 映射

传统做法是 PowerShell 脚本或商业 EDR 取证模块——要么人工编排，要么重量级 agent。

💡 核心问题：能不能有一个轻量的、单二进制的、本地运行的 AI Agent，用自然语言驱动整个 IR 流程？

RustAgent 就是这个问题的答案。单二进制 ~34MB，无需安装，启动即用。

02 六层架构详解

① Agent Loop — 核心循环

问模型 → 检查工具调用 → 执行 → 回写结果 → 继续。while 循环 + 安全阀 + 自修复。

② Model Layer — 模型适配

OpenAI-compatible 统一接口，支持任意 Provider（OpenAI、Azure、Ollama、vLLM、DeepSeek…）。

③ Tool Layer — 工具系统

34+ 内置工具 + MCP 动态注册 + 外部工具。每个工具声明 category，由 Permission System 管控。

④ Safety Layer — 安全纵深

三层防御：Permission Gates → Bypass Detection → Intent Policy。Rust 层面硬拦截。

⑤ Skill Layer — 知识注入

渐进式加载：加权评分按需注入，不预加载所有 Skill 到 prompt。CJK 分词支持中英文混合匹配。

⑥ Infrastructure — 基础设施

SQLite 记忆、Checkpoint 崩溃恢复、AES-256-GCM 加密、CRON 调度、YARA 扫描、JSONL 事件日志。

03 Agent Loop — 核心循环

Agent Loop 的本质是一个 while 循环：

for iteration in 0..max_iter {
    // 1. 调模型（流式）
    let response = provider.chat_stream(&model, &messages, &tools, tx).await?;

    // 2. 提取工具调用
    let tool_calls = extract_tool_calls(response);

    // 3. 没有工具调用 → 结束
    if tool_calls.is_empty() {
        break;
    }

    // 4. 执行工具，回写结果
    for tc in tool_calls {
        let result = execute_tool(tc).await;
        history.push(ChatMessage::tool(tc.name, result));
    }
}

03 Agent Loop — 关键设计决策

🔒 max_iterations 安全阀

模型可能陷入无限工具循环。默认 100 轮上限 + rabbit hole detection：连续 N 轮（默认 5）只调工具无文本回复，强制要求总结。

🔧 Re-prompt 自修复

小模型常返回「我来帮你查」但不发工具调用。检测到意图明确但工具调用缺失，自动注入 re-prompt 重试，最多 2 次。

if tool_calls.is_empty() && !has_executed_tools && reprompt_count < 2 {
    if mentions_tool || has_intent_phrase {
        history.push(ChatMessage::user("Please use tool call format..."));
        reprompt_count += 1;
        continue;
    }
}

03 上下文窗口管理

LLM 有上下文窗口限制。RustAgent 用 CJK-aware token 估算 + 优先级裁剪，分 4 阶段逐步压缩：

阶段裁剪目标保留长度
Phase 1旧工具结果100 字符
Phase 2旧 assistant 回复200 字符
Phase 3旧用户消息100 字符
Phase 4旧工具结果进一步裁剪50 字符

最近 6 条消息 永远不会被裁剪，保证上下文连贯。

文本工具调用提取：支持三种格式——JSON code block、内联 JSON、XML 风格，不依赖原生 function calling。

04 Expert Mode — 长任务架构

短任务（Instant 模式）用单次 Agent Loop 完成。但复杂 IR 任务可能需要数十分钟甚至数小时——单次 Loop 的上下文窗口无法承载。

Expert 模式引入 Manager-Executor-Auditor 三角色分离：

🧠 Manager（规划者）

每轮只接收 TaskContract（无历史），规划下一个子任务。新鲜上下文，杜绝上下文漂移。

⚡ Executor（执行者）

复用现有 Agent Loop，以精炼 brief 为输入。每轮独立上下文，最多 N 次工具调用。

🔍 Auditor（验证者）

独立验证 Executor 产出：文件是否存在、进程是否已终止、证据是否有效。只有验证通过的发现才进入 TaskContract。

📋 TaskContract（状态合约）

持久化到 SQLite（Schema v5）。包含 IR 阶段、已验证发现、已验证动作、开放线索。崩溃后可恢复。

IR 阶段推进：Collection → Analysis → Attribution → Containment → Eradication → Reporting → Done。Manager 声明下一阶段，只允许前进不允许后退。

04 Expert Mode — 关键机制

🔐 PermissionProfile 预授权

长时间无人值守时， containment 动作（杀进程、停服务、删持久化）不能每次都等人工审批。PermissionProfile::ir_containment() 预授权特定动作类别，破坏性操作永远不预授权。

// 意图级匹配：只放行特定命令模式
match tool_name {
    "shell_exec" => {
        if cmd.contains("taskkill") || cmd.contains("stop-process") {
            return profile.is_preauthorized(KillProcess);
        }
    }
    "ir_persistence" => { /* remove/delete → RemovePersistence */ }
}

⏱ 分级工具超时 + 存活看门狗

阶段超时场景
Immediate30s快速查询（进程列表、文件读取）
Standard300s常规工具（YARA 扫描、网络分析）
Extended900s深度分析（malware_deep）
Watchdog24h超长任务（ir_memdump）— 存活看门狗管控

Watchdog 阶段： wall-clock 超时设为 24h（实际不触发），真正的中止机制是 存活看门狗——如果工具在 N 秒内没有发送任何进度消息，自动中止。

05 AI 模型适配层

核心职责：把不同 LLM Provider 的 API 差异统一成一个接口。

pub struct OpenAiProvider {
    clients: Vec<ModelClient>,  // 每个模型一个 client
}

// 统一接口：不管背后是 GPT-4o、DeepSeek、Ollama 还是 vLLM
pub async fn chat_stream(
    &self, model: &str,
    messages: &[ChatMessage],
    tools: &[ToolDefinition],
    tx: Sender,
) -> Result<(String, Usage, Vec<ToolCall>)>

选择 OpenAI-compatible 协议作为统一标准。任何兼容 /v1/chat/completions 的服务均可直接接入。

多模型 Fallback：主模型连续失败时自动切换到 fallback 模型。端侧场景尤为重要——本地 Ollama 显存不足时 fallback 到云端保证可用性。

06 Tool System — Agent 的手和脚

工具系统让 Agent Loop 可以「做事」。每个工具是一个 Rust 异步函数，接 JSON 参数，返回 String 结果。

工具类别数量示例
IR 取证15+ir_process、ir_network、ir_persistence、ir_scan
系统管理10+shell_exec、file_read、sys_info
Computer Use10+cu_screenshot、cu_mouse、cu_keyboard、cu_window_list
浏览器自动化1browser_cdp

07 安全模型 — 四层纵深防御

LLM 是不可信的。所有安全控制必须在 Rust 代码层面 实现，不能依赖 prompt 指令。

🛡️ 第一层：Permission Gates

5 类工具操作：Read / Write / Delete / Modify / Execute。每类对应一个独立权限门，用户可逐个授权/拒绝。

🔍 第二层：Cross-Category Bypass Detection

检测 Agent 是否用已授权的工具类别绕过未授权的类别。例如用 shell_exec（Execute）删除文件（Delete）。

⚖️ 第三层：Command Intent Policy

对 shell_exec 中的实际命令做意图分析，分为 Block / Audit / Pass 三类策略。

🔐 第四层：PermissionProfile 预授权（Expert 模式）

Expert 模式下，ir_containment Profile 预授权杀进程/停服务/删持久化。意图级匹配，破坏性操作永不预授权。

07 安全模型 — Block 规则示例

Block 规则的准入门槛极高——必须同时满足 (1) 不可逆 (2) 没有合法 IR 用途 (3) 误报概率接近零。

// Block 规则示例：磁盘格式化 — 不可逆，无合法 IR 用途
BlockRule {
    name: "format_volume",
    matches: |intent| intent.verb == Verb::Format,
    explain: |intent| "Format-Volume is an irreversible disk operation",
}

// 只有极少数操作被 Block：
// • Security 日志清除
// • 磁盘格式化
// • 编码/混淆命令
// 其他高风险操作只 Audit 不 Block
设计哲学：Block 是最后一道防线。其他高风险操作通过 Audit 让用户知情决策，而不是武断禁止。

08 Skill System — 渐进式知识注入

把所有知识都塞进 system prompt 会消耗大量 token。RustAgent 采用 渐进式加载：只在需要时注入相关 Skill。

加权评分匹配

name         × 4.0   // 技能名称匹配最重要
description  × 2.5   // 描述匹配次之
triggers     × 2.0   // 触发词匹配
body         × 1.0   // 正文 token 重叠
trigger_substring_bonus = +10.0  // 完整触发短语出现

// 归一化：防止大文档靠 token 数量取胜
final_score = raw_score / sqrt(body_token_count)

CJK 分词

中文逐字切分，ASCII 按词切分，确保中英文混合内容正确匹配。

Slash Command 交互

输入 / 触发技能选择器弹窗。/SkillName 以 ×4.0 权重命中技能名称。

09 Memory System — SQLite + FTS5

RustAgent 的记忆分 两层：

层级存储说明
自动记忆SQLite + FTS5每轮对话自动持久化，支持全文搜索
长期记忆MEMORY.mdAgent 主动 curate 的精炼记忆

Memory Recall

每轮对话开始时，RustAgent 自动从 SQLite 检索与当前消息相关的历史记忆，注入到 context 中。Agent 不需要主动调用任何工具 就能「记住」之前聊过什么。

12 总结

RustAgent 的核心设计收敛到 6 个关键判断：

#1
🛡️ 安全不可妥协

LLM 不可信。四层纵深防御：Permission Gates → Bypass Detection → Intent Policy → PermissionProfile。

#2
📦 端侧优先

单二进制 ~34MB，无需安装，无需网络。所有数据留在本地。

#3
🧠 渐进式知识注入

不把所有 Skill 塞进 system prompt。加权评分按需注入，节省 token。

#4
🔧 工具即能力

40+ 内置工具 + MCP 动态注册 + Computer Use + 并行 IR 采集。

#5
💾 记忆是连续性的基础

SQLite FTS5 自动记忆 + MEMORY.md 长期记忆 + TaskContract 崩溃恢复。

#6
🛠 Expert Mode — 长任务架构

Manager-Executor-Auditor 三角色分离，TaskContract 状态持久化，PermissionProfile 预授权，分级超时 + 存活看门狗。
